# HL 清算地图（hl-liqmap）

Hyperliquid 永续合约的潜在强平分布图。静态前端 + 私有采集 + 公开聚合快照。

- 线上地址：https://xyz1367487.github.io/hl-liqmap/
- 本仓库只含**代码**与**公开聚合**（`aggregate` 分支的 `data/aggregate.json`），不含任何地址或逐账户数据。
- 采集运行在私有仓库 `hl-liqmap-private`，通过 SSH deploy key 单向发布聚合。

## 当前运行状态

> 以下为 **2026-11-22（北京时）** 核对的实际配置，不是计划值。

| 项 | 当前值 |
|---|---|
| 运行环境 | 自托管 runner（Lightsail 新加坡，labels `self-hosted, liqmap`） |
| 快照触发 | `13,43 * * * *`（每 30 分钟） |
| 收割触发 | `40 * * * *`（每小时） |
| 扫描并发 | 12 条持久连接 |
| 每地址 pacing | 0.28 秒 |
| 单轮扫描上限 | 1200 秒（20 分钟）后停止新增，保留进度到下一轮 |
| 历史补查批大小 | 500 个新地址 + 50 个失败重试 / 轮 |
| 限流处理 | 撞到 HTTP 429 时全 worker 退避，基数 5 秒按尝试次数递增 |
| 单仓位准入 | `abs(positionValue) > 5000` 美元（严格大于） |
| 聚合 schema | 3（稀疏绝对价格网格，`bucket_step = reference_mark × 0.0005`） |

实测单轮扫描约 12–13 分钟（约 1 万次 `clearinghouseState` 请求），30 分钟触发有约 17 分钟余量。

限流依据：官方文档 `clearinghouseState` weight = 2，IP 聚合上限 1200 weight/分钟 ⇒ 硬上限 600 请求/分钟。当前用量约 648/分钟，实测零失败；若触发 429 由退避机制自动降速。

## 已知限制（重要）

**本图不是全网全量。** 地址发现依赖订阅成交流，这会产生系统性采样偏差：

- 高频交易者（多做空对冲）更容易被捕捉，低频长线多头更容易被漏掉
- 2026-11-15 实测（BTC）：多头覆盖 **30.7%**（12,027 / 39,021 币）、空头 **45.6%**；全币种多空比在 0.56–0.98 之间，一律偏空
- 因为 `openInterest` 是**单边**计数，不能用「多+空之和」直接与 OI 比较，否则覆盖率虚高

**位置与结构信息是可靠的**（强平堆积在哪个价位、杠杆如何分布），**但绝对金额被低估约三到四成**。不要把图上合计当成全市场总量。

已实测排除的补齐路径：官方排行榜（7,232 个合格地址已 100% 在册）、vault、子账户、其他 9 个 perp dex、币种白名单、区块枚举、官方 S3。唯一根本解法是运行 Hyperliquid 非验证节点（官方要求 16 vCPU / 128 GB / 500 GB，最便宜的可行方案约 €159/月），当前不采用。

## 图表怎么读

- **横轴**为线性美元价格。绿色柱是多头潜在强平名义，红色柱是空头；左轴为每桶美元金额。
- **右轴**为两条同色累计曲线。左右轴相互独立且都是线性，**不能直接比较两轴高度**。
- **累计算法**：多头从当前行情价向下、空头向上，以全部基础桶为输入，在桶的远端强平价极值处**阶跃计入完整金额**，不在桶内部插值。
- **价格窗口**：工具栏滑块可拖动，范围 ±1% 到 ±100%，每跳 1%，拖动即重绘。另有放大/缩小按钮、滚轮缩放（只在绘图区内生效，移到图外滚动页面）、手填上下限、重置范围。
- **hover / 键盘聚焦**：显示价格区间、桶内强平价极值、名义金额、仓位数、同侧累计。
- **分辨率 5/10/25/50bp** 是显示桶宽（1bp = 0.01%，即参考价的 0.05%/0.1%/0.25%/0.5%），**不是杠杆、概率或刷新频率**。基础步长为 `reference_mark × 0.0005`，其余选项只合并相邻的 2/5/10 个基础桶，金额与仓位数守恒。
- **两条价格线**：`reference_mark` 是分桶用的固定参考价，随聚合快照更新；实时现价由浏览器直连行情 API，约 10 秒刷新。现价移动**不代表**私有仓位已重新采集。行情不可用时明确以参考价定位，不冒称实时现价。
- **过期提示**：聚合或 Watchlist 超过 2 小时提示过期，行情超过 60 秒提示行情过期。读取失败会保留旧快照并提示，旧图不能当成新数据。

默认展示真实聚合。**估算层可选**，虚线柱基于假设，不计入真实累计。**本机 Watchlist** 是独立数据源，名单存在浏览器 localStorage，拉取时由浏览器直接请求 Hyperliquid 公开 API，不上传；不与公开聚合叠加，避免重复计数。

## 聚合数据格式（schema 3）

```json
{
  "schema_version": 3,
  "generated_at_unix": 1795333832,
  "privacy": { "scope": "aggregate" },
  "coin_list": ["BTC", "ETH", "..."],
  "selection": {
    "unit": "position_notional_usd",
    "operator": "gt",
    "threshold": 5000,
    "account_equity_min": null
  },
  "markets": {
    "BTC": {
      "reference_mark": 59109.0,
      "bucket_step": 29.5545,
      "buckets": [
        {
          "side": "L", "index": 1, "notional": 248099.33, "positions": 2,
          "px_low": 57.996, "px_high": 58.080,
          "lev": [110303.52, 0.0, 137795.82, 0.0]
        }
      ],
      "lev_unknown": 0
    }
  }
}
```

- 桶区间为 `[index × bucket_step, (index+1) × bucket_step)`，稀疏存储，只含非空桶。
- `lev` 是 4 档杠杆（≤10x / 11–25x / 26–50x / >50x，上界含），实际杠杆不可用时退化为单色柱并计入 `lev_unknown`。
- `selection` 缺省时前端显示「旧快照：账户总值 ≥ $10,000」，不冒称新口径。

校验：

```sh
python3 -B aggregate.py --validate path/to/aggregate.json
python3 -B -m unittest discover -s tests -v
python3 -B tests/browser_harness.py --aggregate path/to/aggregate.json
```

浏览器验证器只暴露前端和校验过的聚合，拒绝访问 `data/`；行情与 Watchlist 为确定性合成响应，不能当作交易行情。

## 数据与隐私边界

- 公开分支 `aggregate` **只有一个文件** `data/aggregate.json`，由发布器约束（既有分支含额外文件即拒绝，无 force push）。
- 公开数据**无地址、无账户列表、无稳定账户标识、无逐账户记录**。
- ⚠️ **不承诺绝对匿名**：单人贡献桶、价格极值、链上关联分析与跨期差分仍可能推断出个别账户。
- 「全网」仅指**已发现且符合准入规则**的账户；无法定位强平价的仓位不计入地图。
- 历史上 `main:data/addresses.json`、`main:data/accounts.json`、`snap:data/snapshot.json` 已从当前公开版本移除，但**分支、旧 Git 历史与旧 blob 仍保留**——这不撤回已公开的数据、第三方下载或缓存。
- 发布用仓库级 deploy key（固定 `aggregate` 分支 + 唯一文件由发布器约束，非 GitHub 分支级权限）。私钥只存在私有仓库 Actions secret，发布后临时目录自动清理。
